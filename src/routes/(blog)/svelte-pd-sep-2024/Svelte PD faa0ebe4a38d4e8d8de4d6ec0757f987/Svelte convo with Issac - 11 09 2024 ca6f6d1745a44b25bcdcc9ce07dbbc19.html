Svelte convo with Issac - 11/09/2024

Summary

  • Focus is on Svelte 5, which has been in release candidate status for a while but feels like a significant improvement over Svelte 4.
  • No confirmed release date for Svelte 5, but it might be released later this year or early next year based on current progress.
  • Svelte 5 appears stable for personal projects but may not be suitable for high-risk client work until fully released.
  • Initial concerns about Svelte 5 becoming too similar to React, but it’s seen as adopting useful concepts, potentially making it easier for React developers to transition.
  • Svelte 5 fixes some of Svelte 4’s shortcomings and is maturing into a more robust framework.
  • While Svelte 5 feels ready for smaller client projects, it might not yet be suitable for large-scale production work.
  • Alternatives like Astro can help integrate Svelte components into existing apps gradually, reducing the risk of adopting a newer framework.
  • Svelte is simpler to learn than React, and Svelte 5 provides familiar concepts, making the transition easier for developers.

Discussion on Svelte Versions

Tim:

Were you looking more at Svelte 4 or 5?

Isaac:

Svelte 5, although it's been in release candidate status longer than I'd like. I started with Svelte 4, but it wasn’t until Svelte 5 that I felt, "this is nice."

Tim:

Svelte 5 looks really good, but the only release date info I can find is “when it's ready.”

Isaac:

Here’s a granular overview, but they could always add more empty boxes: Svelte 5 Status.

Tim:

It’s mostly green, so maybe this year or early next year.

Isaac:

I wouldn’t use it for production client work yet, even if fully released. But it's stable enough for personal projects. Most people recommend staying away from super-new features.

Tim:

Some people say Svelte 5 is becoming more like React, but it also seems to fix many of the remaining issues and is more ready for prime time.

Isaac:

Yeah, the initial reaction was, “Don’t make it more like React,” but I think it shows Svelte’s maturity in adopting useful ideas from React. It could also help transition React devs over to Svelte more easily.

Tim:

Maybe not for huge or high-risk projects, but it seems solid.

Isaac:

I’d choose it over Blazor, which I’ve used on three projects. Perfect for clients with little tech capability, maybe for small functionalities like an admin interface.

Another option is Astro, which can inject components from different frameworks into one app. It could help transition from frameworks like Angular to React or Svelte gradually. You could wrap an existing app in Astro, then slowly move state management and functionality into the new framework. It reduces the risk of choosing a less prominent framework.

Tim:

Svelte is easier to learn than React. With Svelte 5 providing equivalents to React’s common features, it won’t be a big stretch for devs to transition. This Svelte Tutorial gives a good overview. It's based on Svelte 4, but I assume there’s a version for 5 coming.

Isaac:

That might be a good way to quickly understand the changes from Svelte 4 to 5: Component Comparison. Svelte 5 feels familiar but much more ergonomic. Svelte 4 is more like React + MobX State Tree with how stores are used.

Tim:

This Astro? https://astro.build/

Astro builds fast content sites, powerful web applications, dynamic server APIs, and everything in-between. (756 kB)

Isaac:

Yep, specifically their "islands" feature: https://docs.astro.build/en/concepts/islands/

I've only toyed with them/Astro briefly, but the concept appealed to me

Just pushed up a tiny sample where I've used a React + Svelte counter component using shared state managed in Astro: https://github.com/vivecuervo7/astro-sample-web-app
