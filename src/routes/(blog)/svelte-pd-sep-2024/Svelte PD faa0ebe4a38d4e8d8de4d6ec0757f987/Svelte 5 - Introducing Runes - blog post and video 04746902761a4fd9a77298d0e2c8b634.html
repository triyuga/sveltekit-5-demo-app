Main new thing in Svelte 5 is the Runes, see the Introducing runes blog post.

Essence

  • state rune replaces reactive $ label and stores
  • effect rune replaces lifecycle methods likeonMount
  • props rune replaces stores, export syntax, and other complexities.
  • The changes are opt-in, allowing gradual adoption
  • See Svelte4 vs Svelte 5 - Component Party

Summary

Rich Harris explains how Svelte's new Runes system introduces a more efficient, consistent way to handle state and reactivity in Svelte 5.

Instead of relying on the reactive $ label and stores, Runes streamline the process. The example used is a counter app, where reactive variables are now marked with the state Rune, and updates are managed with the derived Rune for dependency tracking.

The speaker highlights how Svelte's current reactivity model can be inefficient, especially with large datasets, and how Svelte 5 addresses this by minimizing unnecessary recalculations. The tutorial shows that the new Runes approach makes it easier to encapsulate logic and move it into external modules without affecting functionality.

Runes also eliminate the need for lifecycle methods like onMount by using the effect Rune, simplifying code structure and allowing effects to run in response to changes.

The props Rune simplifies the way props are declared and handled, removing the need for stores, export syntax, and other complexities.

Overall, Svelte 5 aims to make apps smaller, faster, and easier to manage, providing a more seamless experience, particularly for maintaining large codebases. The changes are opt-in, allowing gradual adoption while maintaining compatibility with existing components.
